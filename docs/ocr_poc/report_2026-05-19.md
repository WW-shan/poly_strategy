## TL;DR

跑了一个最小可演示的 pipeline 验证 OCR/PDF 路径能不能给 #11 的 spec 加价值。结论是 mixed：

- ✅ **Pipeline e2e 通** — Federal Register API → 真实 PDF → pypdf 抽文本 → LLM 抽 fact 占位，3/3 测试样本成功
- ⚠️ **但现代主流 source family 不需要 OCR** — 现代 SEC 8-K 0% 是 PDF、现代 Federal Register PDF 100% 有 text layer
- 🎯 **OCR 真实价值在 spec 没显式列的地方**：CourtListener 早期 docket scan、FDA Form 483、EPA 执法 PDF、老 SEC 附件、外国监管文件

→ **OCR 不应该作为 spec PR 2 的核心 connector**，但**应该作为 spec PR 2 的 fallback 层**（当主 source 是 text-only API + 附件包含 PDF 时启用）。这跟我在 issue #11 回复里写的 angle 一致，**但 narrower**。

## OCR 真实价值在哪里（修正 #11 回复里的方向）

我在 #11 回复说"SEC 8-K exhibits 常是 PDF"——**现代 filing 实测推翻了这个**。修正后的 angle：

| Source family | 现代是否需要 OCR | 备注 |
|---|---|---|
| SEC EDGAR (modern, post-2010) | ❌ 不需要 | HTM/XBRL 全包 |
| Federal Register (modern) | ❌ 不需要 | PDF 都有 text layer |
| CourtListener early dockets (pre-2010) | ✅ **需要** | 大量 scan-only PDF |
| FDA Form 483 / 警告信 | ⚠️ **部分需要** | 实测样本需补 |
| EPA / OSHA 执法记录 | ⚠️ **部分需要** | 同上 |
| 公司年报 PDF exhibit（特定 8-K like material agreement）| ⚠️ **偶有需要** | 表格图像 / 老附件 |
| 外国监管文件（中国证监会、德 BaFin、英 FCA）| ✅ **需要** | 全球扩展时关键 |

**含义**：OCR 不是 spec PR 2 的主体，是 PR 2 的**conditional fallback**。pseudo-code：

```python
def fetch_filing(filing):
    text = try_text_api(filing)
    if text:
        return text
    pdf = try_pdf_url(filing)
    if pdf and has_text_layer(pdf):
        return pypdf_extract(pdf)
    if pdf:  # scan-only PDF
        return ocr_extract(pdf)  # 这一层才是我能加的价值
    return None
```

## 局限性 + 下一步

**这次 POC 没做的事**：
- 没拉**任何 scan-only PDF** 实测（手头没找到稳定 source；CourtListener API 需 auth）
- 没真调 LLM（用占位 regex；生产换成 OpenRouter Gemini Flash 即可）
- 没跑 Polymarket market mapping（FR notice 跟 active market 的 fact-need 还没接上）

**值得做的下一步（取决于 WW-shan 在 #11 怎么 react）**：

1. **找 1 个 scan-only PDF 测**（FDA Form 483 archive 或 court PACER recap）证明 pypdf 失败 + tesseract / Gemini Vision 拿到 → 真正展示 OCR 价值
2. **挑 1 个 Polymarket 已 resolve 的 SEC/FDA 关联 market**，找它的 official document 时间戳 + market price history，**验证 fact 是否真早于价格变化**（这是 spec 的核心 thesis）
3. **接 OpenRouter gemini-flash 替换 stub_llm_fact_extraction**，按 spec 的 `structured_fact` schema 抽取
